# Scan3D — 3D-сканер предметов камерой телефона

Приложение для Android в духе KIRI Engine (режим «фото-скан»): вы обходите предмет с телефоном,
приложение само делает кадры и показывает, с каких сторон уже снято. Кадры уходят на ваш сервер
на Render, он собирает из них 3D-модель, и она возвращается в телефон. Модель можно крутить
и экспортировать в GLB, OBJ, PLY или STL.

```
app/      Android-приложение (Capacitor: HTML/JS + нативная оболочка)
server/   сервер фотограмметрии (Python + COLMAP), Docker-образ для Render
.github/  сборка APK и проверка сервера в GitHub Actions
render.yaml  настройки Render (Blueprint)
```

## Шаг 1. Загрузите проект на GitHub

1. Создайте на github.com новый репозиторий, например `scan3d` (Public или Private).
2. Загрузите в него **содержимое** этой папки так, чтобы `README.md`, `render.yaml`, `app/`,
   `server/` и `.github/` лежали в корне репозитория.
   - Через сайт: «Add file → Upload files», перетащите все файлы и папки, затем «Commit changes».
   - Через git: `git init && git add . && git commit -m "Scan3D" && git branch -M main && git remote add origin https://github.com/ВАШ_ЛОГИН/scan3d.git && git push -u origin main`
3. Проверьте, что в репозитории есть файл `.github/workflows/build-apk.yml`. Браузер иногда
   пропускает папки с точкой в начале. Если файла нет, создайте его через «Add file → Create new file»
   (в поле имени введите `.github/workflows/build-apk.yml`) и вставьте содержимое из этой папки.
   Так же добавьте `.github/workflows/server-check.yml`.

## Шаг 2. Получите APK

Сборка запускается сама после загрузки (вкладка **Actions**, «Build APK», около 5–8 минут).
Если не запустилась: Actions → Build APK → «Run workflow».

Готовый файл:
- **Releases** (справа на главной странице репозитория) → последняя «Scan3D сборка N» → `Scan3D.apk`.
  Это удобнее всего открыть прямо с телефона.
- или Actions → нужный запуск → Artifacts → `Scan3D-apk` (zip с APK внутри).

Установка: откройте APK на телефоне и разрешите установку из неизвестных источников.
Нужен Android 7 или новее. APK подписан отладочным ключом: для личного использования этого
достаточно, для Google Play нужна отдельная подпись.

## Шаг 3. Запустите сервер на Render

1. render.com → **New → Blueprint** → подключите GitHub и выберите репозиторий `scan3d`.
2. Render прочитает `render.yaml` и предложит сервис `scan3d-server` на плане **Standard**
   (1 CPU, 2 ГБ). Нажмите **Apply / Deploy**. Первая сборка Docker-образа занимает 10–15 минут.
3. Когда статус станет **Live**, скопируйте адрес вида `https://scan3d-server-xxxx.onrender.com`.
   Откройте его в браузере: должна появиться страница «Scan3D server работает» и «COLMAP: найден».
4. На вкладке **Environment** сервиса скопируйте значение `API_KEY`: Render сгенерировал его сам,
   чтобы ваш сервер не могли нагружать посторонние.

> Почему не бесплатный план: у него 0.1 CPU и 512 МБ памяти. Фотограмметрия на нём идёт
> десятки минут и часто падает по памяти. Можно попробовать: поменяйте `plan: standard` на
> `plan: free` в `render.yaml` и выбирайте в приложении качество «Быстро», но работа не гарантирована.
> Цены планов смотрите на render.com/pricing.

## Шаг 4. Подключите приложение к серверу

Приложение → значок настроек → вставьте **адрес** и **ключ доступа** → «Проверить сервер».
Должно появиться «Сервер работает».

Чтобы адрес был вписан в приложение заранее: GitHub → Settings → Secrets and variables →
Actions → вкладка **Variables** → New variable `SERVER_URL` со значением адреса сервера,
затем пересоберите APK (Actions → Build APK → Run workflow). Ключ всё равно вводится в настройках:
вшивать его в APK небезопасно.

## Как снимать, чтобы модель получилась

- Предмет размером от кружки до стула, матовый, с рисунком или фактурой. Блестящие, прозрачные
  и однотонные гладкие предметы фотограмметрия не восстанавливает (это ограничение метода,
  KIRI Engine для них предлагает отдельный режим).
- Поставьте предмет на стол с узором, газетой или ковриком: фон с деталями помогает найти положение камер.
- Ровный рассеянный свет, без резких теней. Сам предмет не двигайте, двигайтесь вы.
- Режим **Авто**: нажмите круглую кнопку и медленно обходите предмет. Кадр делается
  примерно каждые 12° поворота и только если он резкий.
- Купол слева внизу показывает покрытие: внешнее кольцо — низкий круг, среднее — телефон выше,
  внутреннее — съёмка сверху. Пройдите 2–3 круга на разной высоте, всего 40–80 кадров.
- Держите телефон вертикально всю съёмку и держите предмет в пунктирном круге.

Время обработки на плане Standard: «Быстро» примерно 5–10 минут, «Обычное» 15–25 минут.
Приложение можно закрыть, результат подхватится при следующем запуске.

## Что умеет и чего нет

Есть: съёмка с контролем резкости и покрытия, ручной режим и фонарик, проверка кадров перед
отправкой, три уровня качества, автоматическое удаление стола и фона, очередь задач на сервере,
продолжение после закрытия приложения, библиотека сканов на телефоне, 3D-просмотр (цвет, глина,
сетка, автовращение), экспорт GLB/OBJ/PLY/STL через «Поделиться».

Нет по сравнению с KIRI Engine: текстуры в виде картинки (UV) — цвет хранится в вершинах,
поэтому мелкие надписи выглядят размыто; LiDAR-режим; режим для бесфактурных предметов;
редактор меша (обрезка, заполнение дыр). Дно предмета, стоящего на столе, остаётся открытым.

## Как это устроено

1. Телефон снимает кадры с видеопотока камеры (одинакового размера, до 1600 px), оценивает
   резкость и по датчику ориентации отмечает покрытие.
2. Сервер (`server/app/pipeline.py`):
   COLMAP находит признаки, сопоставляет кадры и восстанавливает положение камер (на CPU) →
   карты глубины методом plane sweep с проверкой согласованности между кадрами (`dense.py`) →
   слияние в TSDF-объём, вырезание стола и фона, marching cubes, очистка и сглаживание (`fusion.py`) →
   экспорт (`meshio.py`).
3. Приложение скачивает модель в своё хранилище и удаляет задачу с сервера.

## Настройки сервера (переменные окружения)

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `API_KEY` | пусто | Если задан, приложение должно передавать этот ключ |
| `COLMAP_THREADS` | 2 | Потоки COLMAP (на плане Standard — 1) |
| `MAX_CONCURRENT` | 1 | Сколько сканов обрабатывать одновременно |
| `MAX_FRAMES` | 120 | Предел загружаемых кадров на один скан |
| `JOB_TTL_HOURS` | 24 | Через сколько часов удалять старые задачи |

Диск на Render временный: после перезапуска сервера незавершённые задачи пропадают,
приложение тогда покажет ошибку с кнопкой «Повторить» (кадры хранятся на телефоне).

## Проверка и локальный запуск

- `server/tests/` — тесты: синтетическая сцена (`synthetic_test.py`), пайплайн с поддельным
  COLMAP (`pipeline_test.py`), HTTP API (`api_test.py`), полный прогон с настоящим COLMAP
  в Docker (`colmap_e2e.py`). Workflow «Server check» запускает их все при изменении `server/`.
- Сервер на своём компьютере: `docker build -t scan3d server && docker run -p 10000:10000 scan3d`,
  в приложении укажите `http://IP-компьютера:10000` (телефон и компьютер в одной сети).
- Приложение в браузере (камера работает на localhost): `cd app/www && python -m http.server 8080`,
  откройте `http://localhost:8080`.
